3. FACILITATOR  (Solana-native x402 settlement)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These three endpoints are the Solana counterpart to Coinbase's EVM facilitator.
Any x402 server can point `facilitator.url` at these to outsource verification
and settlement.

──────────────────────────────────────────────────
GET /facilitator/supported
──────────────────────────────────────────────────
→ 200 {
    networks: ["solana-mainnet"],
    schemes: ["exact"],
    assets: [
      { mint: "<USDC_MINT>", symbol: "USDC", decimals: 6 },
      { mint: "<CLAWD_MINT>", symbol: "CLAWD", decimals: 9 }
    ]
  }

──────────────────────────────────────────────────
POST /facilitator/verify
──────────────────────────────────────────────────
Body: {
  paymentHeader: string,   // base64 signed VersionedTransaction
  requirement:  string     // base64 PaymentRequirement JSON
}
→ 200 { isValid: true,  payer: "<base58>", signature: "<tx-sig>" }
→ 200 { isValid: false, invalidReason: string }
→ 400 { isValid: false, invalidReason: "missing fields" }

──────────────────────────────────────────────────
POST /facilitator/settle
──────────────────────────────────────────────────
Body: same as /verify
→ 200 { success: true,  txHash: "<solana-sig>", networkId: "solana-mainnet", payer: "<base58>" }
→ 400 { success: false, error: string }
→ 502 { success: false, error: string }   // broadcast failed

Agents are stored as PDAs on Solana. The gateway reads them at request time —
no separate database.

    splitTreasuryBps?: number,

    protocols: {
      x402: boolean,
      mpp:  boolean,
      ap2:  boolean,
      a2a:  boolean
    }

6. PAYMENT-GATED AGENT CALLS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

All methods below follow the same two-leg pattern:
  Leg 1 — no payment → 402 challenge
  Leg 2 — attach payment → 200 resource

The gateway negotiates the protocol from request headers (see §8).

──────────────────────────────────────────────────
POST /a2a/:agentId                (A2A JSON-RPC)
──────────────────────────────────────────────────
Body: A2A JSON-RPC envelope
  { method: "tasks/send", params: { ... } }

Without payment → 402 + challenge headers
With payment    → proxies to agent, returns A2A response

──────────────────────────────────────────────────
ALL /agents/:agentId/*            (passthrough proxy)
──────────────────────────────────────────────────
:agentId = registered agent id
/* = any sub-path (GET / POST / PUT / DELETE supported)

Without payment → 402 + challenge headers
With payment    → gateway proxies the request to agent.endpoint,
                   forwarding all headers plus:
                     x-clawd-payer:     <payer base58>
                     x-clawd-signature: <settlement tx sig>

Response decorations (added by gateway on success):
  payment-response:     base64 JSON  { signature, network }
  x-clawd-receipt-cid:  IPFS CID of the settlement receipt
  x-clawd-discount:     "tier=N; bps=N"  (when $CLAWD discount applied)

Pricing fallback: 0.01 USDC per call if no on-chain pricing entry exists.

8. PAYMENT PROTOCOL REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The gateway negotiates the protocol from request headers.
Default when no header is set: x402.

  Protocol  | Signal header                               | Payment header
  ──────────|─────────────────────────────────────────────|──────────────────────────
  x402      | Accept: application/x402+json               | PAYMENT-SIGNATURE: <b64tx>
            | (or no header — default)                    | (also: X-PAYMENT: <b64tx>)
  MPP       | Accept: application/mpp+json                | Authorization: Payment method=solana-exact, tx="<b64tx>"
            | Authorization: Payment ...                  |
  AP2       | X-AP2-Mandate: <jwt-vc>                     | PAYMENT-SIGNATURE: <b64tx>
  A2A       | route to /a2a/:id (body shape signals it)   | same as chosen inner protocol

Optional: advertise payer for discount pre-check:
  X-Payer: <base58 wallet pubkey>

Advertised by gateway on 402 responses:
  Accept-Payment: x402, mpp, ap2, a2a
  X-Payment-Protocols: x402,mpp,ap2,a2a

9. 402 CHALLENGE BODY SHAPES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

x402 challenge (status 402, Content-Type: application/json):
  {
    x402Version: 1,
    accepts: [
      {
        scheme:             "exact",
        network:            "solana" | "solana-devnet",
        resource:           string,    // the requested path
        description:        string,
        payTo:              string,    // base58 — treasury ATA owner
        asset:              string,    // base58 — USDC or $CLAWD mint
        maxAmountRequired:  string,    // base units, e.g. "10000" = 0.01 USDC
        maxTimeoutSeconds:  number,    // 60
        extra: {
          decimals:         number,
          recentBlockhash?: string,    // must use this blockhash when signing
          memo?:            string
        }
      }
    ],
    error: "Payment Required"
  }
  Header: PAYMENT-REQUIRED: <base64 of accepts[0]>

MPP challenge (status 402):
  {
    methods: [
      {
        network:   string,
        recipient: string,   // base58
        asset:     string,   // base58 mint
        amount:    string,   // base units
        decimals:  number,
        nonce:     string    // recentBlockhash
      }
    ]
  }

AP2 challenge (status 402):
  {
    maxAmount:  string,
    asset:      string,
    resource:   string,
    settlement: { network: string, recipient: string, decimals: number }
  }

10. $CLAWD HOLDER DISCOUNTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Send X-Payer: <wallet> on any gated call before attaching payment.
The gateway checks your $CLAWD ATA balance and discounts maxAmountRequired.

  Tier 1  —  DISCOUNT_TIER_1_BALANCE tokens   →  DISCOUNT_TIER_1_BPS basis points off
  Tier 2  —  DISCOUNT_TIER_2_BALANCE tokens   →  DISCOUNT_TIER_2_BPS basis points off
  Tier 3  —  DISCOUNT_TIER_3_BALANCE tokens   →  DISCOUNT_TIER_3_BPS basis points off

(Exact thresholds are configured per-deployment in env vars.)
Discount is surfaced in the 402 challenge as:
  X-Clawd-Discount: tier=N; bps=N

11. REVENUE SPLIT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Each settled payment is split four ways (basis points, sum to 10000):
  owner     — agent creator
  buyback   — $CLAWD buyback wallet
  treasury  — protocol treasury
  operator  — gateway operator

Per-agent overrides possible via on-chain registry (splitOwnerBps etc.).
Receipt written to IPFS (Pinata) after every settlement.
Receipt header: X-Clawd-Receipt-CID: <ipfs-cid>

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

import { clawdFetch, getAgentCard, getRegistryEntry } from "@solanaclawd/x402-client";

// ── clawdFetch ──────────────────────────────────────────────────────
// Drop-in fetch that auto-pays 402s on Solana using p-token (105 CU vs 6200).

const res = await clawdFetch("https://x402.wtf/agents/<id>/summarize", {
  method: "POST",
  body: JSON.stringify({ url: "https://example.com" }),
  signer,                // Keypair
  connection,            // Connection (Helius RPC recommended)
  protocol: "x402",      // "x402" | "mpp" | "ap2"  (default: x402)
  advertisePayer: true,  // sends X-Payer header for discount check
  onPaymentRequired: async (req) => {
    // req.maxAmountRequired in base units — show UI or auto-approve
    return confirm(`Pay ${Number(req.maxAmountRequired)/1e6} USDC?`);
  },
});

console.log(res.receiptCid);  // IPFS receipt CID
console.log(res.signature);   // Solana tx signature

// ── Discovery ───────────────────────────────────────────────────────
const card = await getAgentCard("https://x402.wtf", "<agentId>");
// → A2AAgentCard { name, description, skills, pricing }

const entry = await getRegistryEntry("https://x402.wtf", "<agentId>");
// → AgentRecord (on-chain data)

13. FULL FLOW — STEP BY STEP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Discover
   GET /api/x402/catalog
   → pick a liveRoute with apiPath + price

2. (Optional) Get agent details
   GET /registry/<agentId>
   GET /a2a/<agentId>/.well-known/agent.json

3. First call (no payment)
   POST /agents/<agentId>/summarize
   Headers: { X-Payer: "<wallet>" }
   → 402 { accepts: [challenge], x402Version: 1, error: "Payment Required" }
   Headers returned:
     PAYMENT-REQUIRED: <base64 challenge>
     Accept-Payment: x402, mpp, ap2, a2a
     X-Clawd-Discount: tier=1; bps=500  (if $CLAWD holder)

4. Build + sign Solana transfer
   - Use challenge.extra.recentBlockhash as transaction blockhash
   - Transfer challenge.maxAmountRequired of challenge.asset to challenge.payTo
   - Use p-token program for 98% cheaper CU (auto-handled by clawdFetch)
   - Serialize tx → base64

5. Retry with payment
   POST /agents/<agentId>/summarize
   Headers: { PAYMENT-SIGNATURE: "<base64 tx>" }
   → 200 + resource body
   Response headers:
     PAYMENT-RESPONSE: <base64 { signature, network }>
     X-Clawd-Receipt-CID: <ipfs-cid>
     X-Clawd-Payer: <base58>

6. Verify settlement (optional)
   POST /facilitator/verify { paymentHeader, requirement }
   → { isValid: true, payer, signature }
